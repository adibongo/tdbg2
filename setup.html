Before Monday — setup

What to install, what it costs, and what to do if your laptop is locked down

This page is longer than a setup page usually is, because it tries to explain what each piece of software is and why the week needs it, rather than simply listing commands to paste. If you have never installed a programming toolchain before, that context is the difference between following instructions and understanding what you are doing — and the second is much less unnerving when something goes wrong.

If you have done all this before, the tables and the code blocks are the whole story and you can skim the prose in between.

Read this first

We cannot install software on a laptop we have never seen. If your organisation manages your machine — and many of yours will — some of what follows will need a conversation with your IT function first. That is completely normal and it is not a sign that anything has gone wrong.

It is also why there is a setup clinic with a technician on hand, and a pre-built cloud workspace for anyone whose laptop is locked down. Between those two, nobody spends Monday morning fighting an installer while the room moves on without them.

If you already know your laptop is managed, email the address at the bottom of this page now, rather than on Sunday night. A fortnight’s notice makes this a routine matter; a few hours’ notice makes it a scramble.

The three tiers

You do not need everything on this page. Work out which tier you are in, and install that.

Tier 1 · Essential Tier 2 · Recommended Tier 3 · If you are going deeper
Query engine DuckDB DuckDB + Parquet workflow
Analysis — R + Positron or RStudio + Python
Reporting — Quarto + LaTeX (TinyTeX)
Delivery Excel (you have it) Power BI Desktop Quarto dashboards
Assistant Any assistant, in a browser + Positron Assistant + a local model
Version control — Git + a GitHub account

Tier 2 is the programme’s actual requirement, and we would rather say so here than discover it together on Wednesday morning.

Tier 1 will carry you comfortably through Monday and Tuesday. Monday’s strategy work needs no tooling at all, and every Day 2 exercise — the SQL session, the laptop warehouse, joins, the quality contract — has a browser-and-DuckDB path through it that genuinely works.

From Wednesday the honest position changes. Forecasting with intervals, segmentation, propensity and leakage, and Thursday’s reproducible reporting all assume that R and Quarto are sitting in front of you. There is a DuckDB-only route through the arithmetic, and people have taken it successfully, but you will spend the second half of the week reading somebody else’s output rather than producing your own. Thursday’s lab, whose entire point is a document that regenerates itself when the data changes, does not really exist without Quarto.

So the recommendation is simple: install Tier 2 before you arrive. If your IT department will not permit it, that is a common and entirely reasonable situation rather than a failure on your part, and it is exactly what the pre-built cloud workspace exists for. Ask for it at the setup clinic rather than arriving on Wednesday and hoping.

Tier 3 is for the analytics leads in the room and is genuinely optional. Nothing in the assessed work depends on it.

Why we are telling you this

A programme that spends a full day on governance should not open by implying there is a free lunch.

Some of this stack costs nothing at all. Some of it does cost money, and some of it needs permission from your IT department — which is precisely what you would expect of tooling that touches company data. We would rather you arrived on Monday already knowing which is which than discovered it in week three, when you try to share a dashboard with a colleague and find that sharing is the part that is licensed.

Nothing in the assessed work requires you to spend money. Where a paid tool appears, the free substitute is named and we will say what it gives up.

Installing

Everything below follows the same shape: what the thing is, why the week needs it, the command, what a successful result looks like, and what to do if it does not appear.

DuckDB — everybody, ten minutes

What it is. A database engine that runs entirely inside a single file on your own laptop. There is no server to install, no account to create, and nothing leaves your machine. Think of it as a spreadsheet engine that has no row limit and speaks the same language as your warehouse.

Why the week needs it. It is the one genuinely non-negotiable install, because it is what lets you query the course data directly. In most corporate environments it installs without administrator rights, since it is a single executable rather than a system-wide package — which is exactly why we chose it for a room full of managed laptops.

Use whichever of these matches your operating system:

# macOS
brew install duckdb

# Windows
winget install DuckDB.cli

# Or download the single binary from duckdb.org/docs/installation

Then check that it works:

duckdb -c "SELECT 'ready' AS status, version() AS duckdb"

What success looks like. A small table printed in your terminal with two columns — status showing ready, and duckdb showing a version string. The exact version does not matter; the fact that it printed anything at all means the install worked.

If it does not work. The usual message is some variant of “command not found”, which almost always means the installer worked but your terminal does not yet know where to look. Closing the terminal and opening a fresh one resolves it most of the time, because the new window picks up the updated path. If it persists, download the single binary from the address above, put it somewhere you can find, and bring the error message to the clinic.

And this is the friendliest thing in the whole stack, for anyone who would rather not spend the week in a terminal:

duckdb -ui

That opens a notebook in your browser — tables down one side, queries and results and charts in the middle. Nothing is uploaded anywhere; the browser is just the interface to the engine running on your own machine. Several people in every cohort do most of the week here, and they are not at a disadvantage.

R and an IDE — Tier 2

What it is. R is a programming language built for working with data; an IDE is the application you write and run it in. You need both, in that order, because the IDE is the front door and R is the engine behind it.

Why the week needs it. From Wednesday onwards, forecasting, segmentation and reproducible reporting all run in R. You will not be writing it from scratch — the assistant does that — but it needs to be installed for you to run and inspect what it writes. Any release from 4.1 onwards works (check with R --version); the latest is best.

  1. R from cloud.r-project.org — take the latest release.
  2. An IDE: Positron (R and Python in one place, with an AI assistant panel) or RStudio Desktop. Either is fine and neither will hold you back. Positron is where the tooling is heading; RStudio is what most people recognise from a screenshot.
  3. Packages. R ships small and gains its capabilities from add-on packages, so this step downloads the specific ones the week uses. Run it once. It takes fifteen to thirty minutes, mostly unattended — start it before Sunday and do something else.
install.packages(c(
  # core. dplyr and lubridate come with tidyverse, but the sessions call them
  # by name, so they are listed by name -- an install list that relies on you
  # knowing what is inside a metapackage is not a list, it is a quiz.
  "tidyverse", "dplyr", "lubridate", "arrow", "duckdb", "DBI", "janitor",
  "scales", "glue",
  # quality
  "pointblank",
  # modelling
  "tidymodels", "fable", "tsibble", "feasts", "pwr", "mclust",
  # causal inference (Friday)
  "fixest", "tidysynth",
  # text (Thursday)
  "tidytext", "tidylo", "irr",
  # reporting
  "quarto", "knitr", "rmarkdown", "openxlsx", "readxl",
  # assistants
  "ellmer", "mall"
))

What success looks like. A great deal of scrolling text, ending without the word ERROR. Warnings are common and usually harmless; errors are the ones to note. The definitive check is the script at the foot of this page, which loads every package by name and tells you which, if any, are missing.

If it does not work. Package installation is the step most likely to go wrong, and it usually goes wrong for one of three reasons: a corporate proxy blocking the download, a missing system library on macOS or Linux, or simply running out of patience and stopping it early. All three are quick for a technician to diagnose and slow to guess at alone. Copy the last twenty lines of output and bring them to the clinic — that text is genuinely all we need.

Quarto — Tier 2

What it is. A publishing tool that turns a document containing both prose and code into a finished report, dashboard or slide deck, running the code as it goes.

Why the week needs it. It is what makes Thursday’s central claim possible: a two-page brief in which every number is computed from the data rather than typed in by hand, so that when the data changes the document changes with it. This very website is built with it.

Download from quarto.org, then check it:

quarto check

What success looks like. A list of checks, each marked with a tick, covering the Quarto installation itself and the R and Python setups it can see. Do not be alarmed if the Python line reports a problem and the R line does not; Quarto reports on everything it looks for, and you only need the parts the week uses.

For PDF output, add the small LaTeX distribution — LaTeX is the typesetting engine that turns a document into a properly laid out PDF, and TinyTeX is a compact version of it that downloads what it needs on demand:

quarto install tinytex

If it does not work. quarto: command not found after a successful install is the same path problem described under DuckDB, and the same fix applies — open a new terminal window. If quarto check reports that it cannot find R, it is usually because R was installed after Quarto; reinstalling Quarto, or simply restarting the machine, resolves it.

Power BI Desktop — Tier 2, Windows only

What it is. Microsoft’s dashboard authoring tool, and the one most likely to be already standard in your organisation.

Why the week needs it. Thursday’s dashboard session is built around designing backwards from a decision, and it helps to practise that in the tool your colleagues will actually open. The principles transfer to any tool; the muscle memory does not.

It is free from the Microsoft Store. On macOS it does not exist — the options are a Windows virtual machine, a remote desktop your organisation provides, or the Power BI web service for viewing only. If you are on a Mac and Power BI matters to you, tell us before Monday and we will pair you appropriately for 4.3. This is a common situation and it is easily handled with a little notice.

An AI assistant — everybody

What it is. The conversational assistant that will write most of the code you run this week, while you read it, question it and correct it.

Why the week needs it. It is the subject of the programme as much as it is a tool for it. Any competent assistant works, and the method transfers unchanged between them. In class we all use the same one, so that everybody is looking at the same screen and the floor staff can help without having to learn your particular setup first.

Check your organisation’s policy before Monday. Some of you will find that a hosted assistant is not permitted for company data. That is frequently a correct policy rather than an obstructive one, and it is exactly the reason the local option below exists — so please do check rather than assume, and tell us what you find.

A local model — Tier 3, and the answer to most policy problems

What it is. A language model that runs entirely on your own laptop, with no network connection and no data leaving the machine.

Why it is here. It is what makes the Thursday classification session available to people whose data genuinely cannot go anywhere. It is slower than a hosted assistant and slightly less accurate, and neither of those matters much for the work we do with it.

# Install a local model runner, then:
ollama pull llama3.2
ollama run llama3.2 "Reply with the single word: ready"

What success looks like. The first command downloads a few gigabytes and shows a progress bar; the second prints a short reply. If the reply is the single word you asked for, everything is working. If it is a chatty sentence containing that word, everything is also working — models vary in how literally they take an instruction, which is itself a small lesson for the week.

If it does not work. The most common causes are disk space and memory: the model needs roughly 8 GB of each. A download that stalls partway usually restarts cleanly if you run the pull command again.

Nothing leaves your laptop. It works offline. It is free. It is worth setting up even if you are fairly sure you will not need it — see 4.2 for where it earns its place.

The data

The course datasets live in the same public repository as this site. Cloning it copies the whole thing to your machine, data included:

git clone https://github.com/bongoadi/turning-data-into-business-growth.git
cd turning-data-into-business-growth
duckdb -c "SELECT COUNT(*) FROM 'data/fmcg_sell_out.csv'"
# 55474

What success looks like. The count printed by the last command matches the number in the comment beneath it. That single line confirms three things at once: the clone worked, DuckDB works, and the file you have is the file we shipped.

No Git? Download the repository as a ZIP from the same address and unzip it anywhere convenient. The data/ folder, plus outputs/, is all you actually need — Git is a convenience here rather than a requirement.

If that address does not open for you. The same files are on this site. Open the Data room page, download each file into a folder called data, and put fmcg_weekly.parquet in a folder called outputs beside it. Then run duckdb -c "SELECT COUNT(*) FROM 'data/fmcg_sell_out.csv'"; it should print 55474.

The setup clinic

Thursday 8 October, 16:00–18:00, online. A technician, plus faculty.

The clinic exists so that installation problems are solved by somebody whose job that is, rather than by you at midnight. Come if any of the following is true — and there is no threshold of seriousness to clear first:

  • Your laptop is managed by your IT department and you cannot install software.
  • The package installation failed and you do not know why.
  • You are on macOS and need Power BI.
  • Your organisation blocks AI assistants.
  • You would rather someone did it with you than read instructions.

That last one is a perfectly good reason on its own, and it is the reason several people give every cohort.

The cloud workspace fallback. If none of this can be resolved on your own machine, we will provision you a pre-built environment that runs in a browser, with everything already installed and the data already loaded. It is a little slower than working locally, and you cannot use it with your own confidential data — but you will not lose a single session, and everything you learn in it applies directly to your own data once you are back at your desk.

Do ask for it early. Provisioning a whole cohort’s environments on Sunday night is a very different task from provisioning three on a Tuesday.

Bring, or do not bring, your own data

Every session in the week works perfectly well with the course datasets. Several people in each cohort deliberately work only with those and get more out of the week for it — the planted defects are the teaching material, and your own data, whatever else is wrong with it, does not have its problems arranged quite so conveniently for learning.

If you do want to work with your own data, four suggestions:

  • Check what you are permitted to take out of your systems, and get it in writing.
  • Prefer shape over content: column names, types, row counts, date range, grain. That is enough for most of the week, and it carries no risk.
  • If you bring real data, keep it on your own machine, do not put it in a hosted assistant, and read 5.4 before you arrive rather than after.
  • Three tables is the right number. Not thirty.

The third of those is the one people most often wish they had followed. Reading the governance session in advance takes twenty minutes and occasionally changes what somebody decides to bring.

The pre-work

Ten days before: your one-page problem charter. There is a template on the capstone page. It is read individually by faculty and it becomes your capstone, so it repays a little thought.

Ten days before: the twenty-minute data-triage diagnostic. It is not a test. It is used to stream the labs and pair people well, so that nobody spends the week either stranded or idle. Nobody sees anybody’s score, including you.

Before Sunday: run the installation check below, and tell us if anything fails. Two quick confirmations first:

duckdb -c "SELECT 'duckdb ok'"
quarto check

Then the R check. This one deliberately loads every package the week actually calls, rather than the three obvious ones, because the failure it is designed to catch is not “R is broken”. It is a single missing package surfacing at 09:20 on Thursday, on conference wifi, across a room full of laptops at once.

Rscript -e '
pkgs <- c("tidyverse","dplyr","lubridate","arrow","duckdb","DBI","janitor","scales","glue",
          "pointblank","tidymodels","fable","tsibble","feasts","pwr","mclust",
          "fixest","tidysynth","tidytext","tidylo","irr",
          "quarto","knitr","rmarkdown","openxlsx","readxl","ellmer","mall")
missing <- pkgs[!sapply(pkgs, requireNamespace, quietly = TRUE)]
if (length(missing)) {
  cat("MISSING:", paste(missing, collapse = ", "), "\n")
  cat("Run: install.packages(c(\"", paste(missing, collapse = "\",\""), "\"))\n", sep = "")
} else cat("R ok - all", length(pkgs), "packages present\n")
'

What success looks like. A single line beginning R ok. If instead you get a line beginning MISSING:, the script has already written out the exact command that fixes it — copy that second line, run it, and run the check again.

Bring the output either way to the clinic. “It said MISSING: tidylo, irr” is a thirty-second fix on the Thursday before the programme. The same words on the Thursday morning of the programme are considerably less convenient, and that is the entire reason this check exists.
