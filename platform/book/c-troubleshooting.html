Appendix C — Troubleshooting

Symptom Likely cause Fix
IO Error: Could not set lock on file ... .duckdb Another R session (or the dashboard) has the warehouse open for writing Close other sessions; open readers with read_only = TRUE; build to a temp file and swap (Chapter 14)
DuckDB file won’t open after copying to another machine It was created by a newer DuckDB version than the one installed install.packages("duckdb") to update, or re-run the pipeline to rebuild the file
Extension Autoloading Error (json, postgres, vss) DuckDB downloads extensions on first use; the network or proxy blocked it Allow extensions.duckdb.org, or INSTALL json; LOAD json; once on a connected machine; or use an R alternative (jsonlite)
₦ or accented letters show as ? or â‚¦ File saved in a non-UTF-8 encoding (Windows “CSV (Comma delimited)”) Ask for “CSV UTF-8”; or readr::read_csv(f, locale = locale(encoding = "latin1"))
Numbers read as text in Excel imports Values stored as text, with commas or currency symbols readr::parse_number() in R or regexp_replace + CAST in SQL (Chapter 7)
Totals are higher than Finance’s A join fan-out from a duplicated dimension key, or duplicate loads Run uniqueness tests on every dimension key; check _source_file counts in bronze
Dashboard doesn’t update after a rebuild The app holds an old connection, or there’s no reactivePoll Open short-lived connections per query; watch the file’s modified time (Chapter 13)
quarto serve says the port is in use A previous app is still running quarto serve 02-dashboard.qmd --port 7788, or stop the old R process
Shiny dashboard works locally but not when deployed Absolute paths, missing packages, or secrets not set on the server Use project-relative paths and config.yml; record packages with renv; set environment variables in the host’s settings
SQL works in DuckDB but fails on PostgreSQL Dialect differences (QUALIFY, GROUP BY ALL, date_trunc arguments) Use a CTE + row_number() instead of QUALIFY; list the GROUP BY columns; check the function docs
Test passes, but the number is still wrong No test covers that failure mode Add a reconciliation test against an external source; ask “what would have caught this?” after every incident
AI-written SQL returns plausible but wrong results Wrong grain, missing filter, average of ratios, unbounded dates Review with the Chapter 5 checklist; add the case to your golden-question set (Chapter 11)
Git wants to commit a 200 MB file Data or databases in the repository Add data/db/, *.duckdb and *.sqlite to .gitignore; remove them from the index with git rm --cached
