10  The semantic layer: one definition of every KPI

🟣 Advanced

What A version-controlled catalogue of business metrics and dimensions, each with Structured Query Language (SQL), meaning and an owner, from which every report, dashboard and artificial intelligence (AI) query compiles its SQL
Why Without it, “revenue”, “active customer” and “default rate” get re-implemented in every tool, slightly differently, for ever
When As soon as a second tool or team consumes gold. Before you introduce an AI assistant, always
Who Metric owners (chief financial officer (CFO) for revenue, chief human resources officer (CHRO) for attrition) approve definitions. Analytics engineers encode them. Everyone consumes

10.1 Anatomy of a metric

A metric is more than a formula:

Part Example Why it matters
Name gross_margin_pct Stable identifier used in code
Label Gross margin (%) What humans see
SQL 100 * SUM(gross_profit_ngn) / NULLIF(SUM(revenue_ngn), 0) The only implementation
Description Gross profit as a share of revenue Removes ambiguity
Format pct Consistent display
Owner Commercial Finance Who approves changes, and who you call
Status certified / exploratory Whether it can go in a board pack
Ratio metrics: sum first, divide last

gross_margin_pct is SUM(gp) / SUM(revenue), not AVG(gp / revenue). The average of ratios gives a small depot the same weight as Lagos Mainland. Encoding the ratio once, correctly, in the semantic layer is exactly how you stop this error recurring.

10.2 Our semantic layer

The Lab’s semantic/metrics.yml (from the dashboard project) is the semantic layer. Here we point it at the gold view:

🧠 Prompt 10.1 — compile and query

Using my metrics.yml and the metric_sql() compiler in kit.R, generate SQL for revenue, gross margin % and stockout rate by region and by quarter for 2025. Print the SQL, run it, and chart revenue by region over quarters.

sql <- metric_sql(layer, c("revenue", "gross_margin_pct", "stockout_rate_pct"),
                  dims = "region", grain = "quarter", where = "year = 2025")
cat(sql)
SELECT date_trunc('quarter', week_starting) AS period,
       region AS region,
       SUM(revenue_ngn) AS revenue,
       100.0 * SUM(gross_profit_ngn) / NULLIF(SUM(revenue_ngn), 0) AS gross_margin_pct,
       100.0 * AVG(stockout_flag) AS stockout_rate_pct
FROM gold.v_sales
WHERE year = 2025
GROUP BY ALL
ORDER BY period
res <- dbGetQuery(con, sql)
ggplot(res, aes(period, revenue / 1e9, fill = region)) + geom_col(position = "dodge") +
  scale_fill_manual(values = c("#0B2C55", "#E8A33D", "#7FA8D4", "#6FBFAE", "#9B8EC4")) +
  labs(x = NULL, y = "Revenue (₦ bn)", fill = NULL)

10.3 Metric trees: explaining why a number moved

Metrics are related. Revenue = units × average selling price, and gross profit = revenue × margin. A metric tree turns “revenue fell” into “volume held, price fell”, which is a different conversation entirely.

🧠 Prompt 10.2 — price-volume bridge

Using the semantic layer’s units and avg_selling_price metrics, decompose the change in revenue between Q4 2024 and Q4 2025 for each category into a volume effect and a price effect (with an interaction term), and show the bridge as a table.

pvm <- dbGetQuery(con, metric_sql(layer, c("revenue", "units", "avg_selling_price"), dims = "category",
                                  where = "quarter = 4 AND year IN (2024, 2025)") |>
                    sub(pattern = "SELECT ", replacement = "SELECT year, ") )
w <- reshape(pvm, idvar = "category", timevar = "year", direction = "wide")
with(w, data.frame(category,
  revenue_change_m = round((revenue.2025 - revenue.2024) / 1e6, 1),
  volume_effect_m  = round((units.2025 - units.2024) * avg_selling_price.2024 / 1e6, 1),
  price_effect_m   = round((avg_selling_price.2025 - avg_selling_price.2024) * units.2024 / 1e6, 1),
  interaction_m    = round((units.2025 - units.2024) * (avg_selling_price.2025 - avg_selling_price.2024) / 1e6, 1)))
category revenue_change_m volume_effect_m price_effect_m interaction_m
Foods 563.8 197.2 318.0 48.7
Beverages 421.2 8.3 410.1 2.8
Home Care 280.3 19.5 254.7 6.1
Personal Care 147.3 -0.5 148.0 -0.2
Snacks 152.2 6.9 143.1 2.2

The three effects add up exactly to the revenue change. Now a category manager can see whether growth came from selling more or from charging more.

10.4 Publish the catalogue into the warehouse

Every tool that connects to the warehouse can then discover the definitions:

semantic_catalogue <- data.frame(
  metric = names(layer$metrics), label = vapply(layer$metrics, `[[`, "", "label"),
  sql = vapply(layer$metrics, `[[`, "", "sql"), description = vapply(layer$metrics, `[[`, "", "description"),
  owner = layer$owner, status = "certified", version = "1.2", approved = as.Date("2026-02-01"))

When the organisation also uses Power BI, keep one source of truth. Either generate DAX from metrics.yml, or treat the Power BI model as the master and export its definitions. Never maintain two by hand.

# Generate DAX measure definitions from metrics.yml (simple aggregates only)
to_dax <- function(m) {
  s <- layer$metrics[[m]]$sql
  if (grepl("^SUM\\(([a-z_]+)\\)$", s)) sprintf("%s = SUM(v_sales[%s])", layer$metrics[[m]]$label, sub("^SUM\\(([a-z_]+)\\)$", "\\1", s))
  else sprintf("-- %s: translate by hand (ratio/conditional): %s", m, s)
}

10.6 Governance of the layer itself

  • Version control. metrics.yml lives in Git, and every change is a reviewed pull request.
  • Ownership. One owner per metric. The owner approves changes.
  • Certification. Only certified metrics may appear in board packs and regulatory returns. exploratory ones carry a badge.
  • Change log. When a definition changes (for example, revenue becomes net of a new levy), note the effective date, and decide whether history is restated.

10.8 ✅ Mastery check

  • Why is the semantic layer the prerequisite for a trustworthy AI assistant?
  • Explain “sum first, divide last” to a non-analyst.
  • What is the difference between a certified and an exploratory metric?
Solutions
  • An AI assistant has to know what “revenue”, “active customer” or “margin” means in your organisation. Without one approved definition per metric, it invents its own, and each answer can differ from Finance’s. The semantic layer gives the model the certified definitions, so its SQL uses the same formulas as the board pack.
  • “If one shop sells ₦1,000 at 50% margin and another sells ₦1,000,000 at 10%, the business’s margin is not 30%. Add up all the profit, add up all the sales, then divide.” Totals first, then the ratio, so big and small units count by their size.
  • A certified metric has an owner, a version and an approval date, and it may appear in board packs and regulatory returns. An exploratory metric is useful for analysis but not yet approved. It carries a badge, and the compiler refuses it for board packs.

10.9 🏢 In the organisation

Start the semantic layer with the ten numbers the executive committee argues about. Put them in a two-hour workshop with their owners, agree the definitions in writing, and encode them the same week. Every later dashboard then inherits the agreement for free.
