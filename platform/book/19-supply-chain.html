19  Playbook: Supply chain and procurement

Sector Supplier performance, lead times, inventory risk

19.1 Decisions this platform supports

  • Supplier management: who delivers on time and in full, and who should get more or less business?
  • Inventory policy: how much safety stock do we need, given actual lead-time variability?
  • Import logistics: which port and incoterm combinations are slow or unpredictable?
  • Stockout prevention: linking late inbound deliveries to outbound stockouts (with the retail sell-out data).

19.2 Architecture mapped to supply chain

Layer In supply chain
Sources Enterprise resource planning (ERP) purchasing (SAP MM, Dynamics 365 supply chain management (SCM), Oracle), warehouse management system (WMS) goods receipts, freight forwarders’ files, port and customs data, supplier portals, Excel trackers
Silver Typed purchase orders (POs); conformed supplier master (SUP-CEDAR = SUP-CEDAR-NG); date errors flagged (received before ordered); one row per PO line
Gold fct_po_lifecycle (accumulating snapshot: ordered → received); dim_supplier; mart_supplier_scorecard; mart_lead_time_stats
Gate Unique PO; received ≥ ordered (or quarantined); order value = qty × unit cost; every supplier in the master; spend reconciles to accounts payable
Govern Metrics: on time in full (OTIF) %, mean and standard deviation of lead time, spend, supplier concentration (top-3 share)
Serve Procurement dashboard; supplier scorecards (Portable Document Format (PDF)) for quarterly reviews; safety-stock parameters back to the ERP
Plane Supplier prices are confidential; contract data is restricted to procurement

19.3 Run the pipeline

spec <- list(
  name = "supply_chain",
  bronze = list(pos = "supply_chain_pos.csv",
                map_supplier = data.frame(source_code = "SUP-CEDAR-NG", conformed_code = "SUP-CEDAR",
                                          reason = "Nigerian subsidiary; same contract")),
  silver = list(
    purchase_orders = "
      SELECT p.po_id, CAST(p.po_date AS DATE) po_date, CAST(p.received_date AS DATE) received_date,
             COALESCE(m.conformed_code, p.supplier_id) AS supplier_id, p.supplier_id AS supplier_id_source,
             p.material_group, p.incoterm, p.port_of_entry,
             CAST(p.order_qty AS INTEGER) order_qty, CAST(p.unit_cost_ngn AS DOUBLE) unit_cost_ngn,
             CAST(p.order_value_ngn AS DOUBLE) order_value_ngn, CAST(p.promised_lead_days AS INTEGER) promised_days
      FROM bronze.pos p LEFT JOIN bronze.map_supplier m ON p.supplier_id = m.source_code
      WHERE CAST(p.received_date AS DATE) >= CAST(p.po_date AS DATE)",
    po_rejects = "SELECT *, 'received before ordered' AS reason FROM bronze.pos WHERE CAST(received_date AS DATE) < CAST(po_date AS DATE)"),
  gold = list(
    fct_po_lifecycle = "
      SELECT *, date_diff('day', po_date, received_date) AS actual_days,
             (date_diff('day', po_date, received_date) <= promised_days)::INT AS on_time
      FROM silver.purchase_orders",
    mart_supplier_scorecard = "
      SELECT supplier_id, COUNT(*) pos, SUM(order_value_ngn) spend_ngn, AVG(on_time) on_time_rate,
             AVG(actual_days) mean_lead, stddev(actual_days) sd_lead, AVG(actual_days - promised_days) avg_slip_days
      FROM gold.fct_po_lifecycle GROUP BY 1"),
  tests = list(
    t_unique("gold.fct_po_lifecycle", "po_id"),
    t_range("gold.fct_po_lifecycle", "actual_days", 0, 365),
    t_custom("order value = qty × unit cost (±₦1)", "SELECT COUNT(*) FROM gold.fct_po_lifecycle WHERE abs(order_qty * unit_cost_ngn - order_value_ngn) > 1"),
    t_custom("quarantined POs ≤ 2%", "SELECT CASE WHEN (SELECT COUNT(*) FROM silver.po_rejects) > 0.02 * (SELECT COUNT(*) FROM bronze.pos) THEN 1 ELSE 0 END"),
    t_custom("no unconformed supplier codes", "SELECT COUNT(*) FROM gold.fct_po_lifecycle WHERE supplier_id = 'SUP-CEDAR-NG'")),
  publish = c("gold.mart_supplier_scorecard"))
sc <- run_pipeline(spec)
show_tests(sc$tests)
status severity test failing_rows
PASS error unique(gold.fct_po_lifecycle: po_id) 0
PASS error range(gold.fct_po_lifecycle.actual_days in [0, 365]) 0

PASS error quarantined POs ≤ 2% 0

19.5 Insight 2: safety stock from real variability

Safety stock protects against variability, not averages. A standard formula, for demand d per day with standard deviation σ_d, and lead time L with standard deviation σ_L:

\[SS = z \sqrt{\bar{L}\,\sigma_d^2 + \bar{d}^2 \sigma_L^2}\]

z <- qnorm(0.95)              # 95% cycle service level
d_bar <- 400; sd_d <- 120     # illustrative daily demand for one material
s |> transform(safety_stock_units = round(z * sqrt(mean_lead * sd_d^2 + d_bar^2 * sd_lead^2))) |>
  subset(select = c(supplier_id, mean_lead, sd_lead, safety_stock_units)) |> head(9)
supplier_id mean_lead sd_lead safety_stock_units

SUP-GONDA 32.705957 13.024761 8644
SUP-FIRTH 20.889878 8.313465 5544
SUP-BRIDGE 17.757113 7.338303 4899

Switching the same material from the least to the most predictable supplier changes the safety stock needed by thousands of units, which is working capital released. That is the business case for the scorecard.

19.7 Deploying in a supply-chain function

  • Owner: Head of Procurement (supplier master and scorecard definitions); Supply Planning (safety-stock parameters).
  • First 90 days: a conformed supplier master and a monthly scorecard; then safety-stock recommendations that the ERP imports (a write-back loop: recommendations go in as a source file, approved by planners).
  • Pitfall: promised lead days typed in by buyers can be gamed. Track who changes them, and compare them with contract terms.
