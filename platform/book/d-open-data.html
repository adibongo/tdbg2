Appendix D — Official and open data catalogue

Every playbook gets better with a macro or sector frame from outside the organisation. This catalogue lists the providers most useful for Nigerian and African business analytics, how to reach them from R, and which playbooks they serve. Treat each one as a source in the architecture: ingest with lineage, cache for offline use, test for freshness, and label its numbers as the provider’s, never your own.

D.3 Rules of the road for external data

  1. Name the source on every chart and table. “₦/US$ (CBN official)” is a different number from a parallel-market rate.
  2. Keep vintages. Official figures are revised. Store the pull date with the data, so a board pack can be reproduced exactly as it was presented.
  3. Separate actuals from projections. IMF WEO mixes both; keep a flag, and let the semantic layer enforce it.
  4. Mind breaks in series. Rebasings (Nigeria’s GDP in 2014, CPI in 2025) mean a chart can show a jump that is a methodology change, not an event.
  5. Check the licence. Most multilateral data is open (Creative Commons (CC) BY 4.0 for the World Bank). Some datasets restrict redistribution. Record the licence in the catalogue.
  6. Cache, then test freshness. APIs change and go down. The Lab’s with_cache() keeps the last good pull, and a freshness test tells you when it is too old.
🧠 Prompt D.1 — wire a new provider in

I want to add [provider] data on [indicator] for [countries, years] to my warehouse. Write a function in the style of R/open_data.R that returns the standard tidy columns (source, dataset, indicator, indicator_name, iso3, country, year, value), caches each pull to data/open/, and falls back to the cache when the API fails. Then write two data tests for it: a freshness test and a plausibility range for the values.
