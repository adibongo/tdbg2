Appendix B — Prompt library

Every prompt in the book, collected automatically from the chapters when the book is built, so this list is always in sync. Use them in class in this order, or pick the ones for the layer you’re working on.

How to use a prompt well
  1. Give context first: paste the table schema (DESCRIBE table), a few rows, and the relevant part of metrics.yml.
  2. Ask for assumptions: end with “list the assumptions you made”.
  3. Review with the checklist from Chapter 5: grain, filters, fan-out, nulls, ratios, sanity total.
  4. Never paste personal data into an external artificial intelligence (AI) tool (Chapter 15).

B.1 The architecture, end to end

Prompt 1.1 — critique an architecture

Here is a draft data architecture diagram [attach image]. Act as a principal data architect reviewing it for a mid-sized Nigerian company. List every problem you see: direction of data flow, layers that are skipped, mislabelled components, missing governance or operations concerns, and anything that would break in production. For each, say why it matters and give the fix. Then propose an improved layered architecture.

B.2 Your workbench

Prompt 2.1 — one-shot installer

Write one R chunk that installs (only if missing) every package I need for a DuckDB-based analytics platform with Quarto and Shiny dashboards: Database Interface (DBI), duckdb, RSQLite, RPostgres, dplyr, dbplyr, tidyr, readr, readxl, writexl, yaml, config, shiny, bslib, bsicons, plotly, DT, httr2, jsonlite, dataverse, targets, ggplot2, knitr. Then print a table of each package with its installed version.

Prompt 2.2 — hello, DuckDB

In R, create an in-memory DuckDB connection, run Structured Query Language (SQL) directly on the comma-separated values (CSV) file fmcg_sell_out.csv without importing it, and show total revenue by year. Then do the same with dplyr on a lazy table and show me the SQL dplyr generated.

B.3 Data comes in many shapes

Prompt 3.1 — read a CSV safely

Read fmcg_sell_out.csv with readr. Show the column types readr guessed. Then read it again forcing every column to text, and explain why a bronze layer might prefer all-text. Show how many values in units_sold are blank, and what blank becomes under each approach.

Prompt 3.2 — tame a presentation spreadsheet

regional_report.xlsx has 4 title rows, region typed once per block (merged cells), one column per month, values as text like “₦149,023,348”, an “All depots” total row and a footnote. Turn it into a tidy table (region, depot, month as a real date in 2025, revenue_ngn as a number). Drop the total and the footnote. Then check: does the sum of depots equal the “All depots” row for January?

Prompt 3.3 — why Parquet?

Convert fmcg_sell_out.csv to Parquet using DuckDB’s COPY command. Compare file sizes and the time to compute total revenue by depot from each. Explain the result in terms of row versus column storage.

Prompt 3.4 — data inventory

List every data file in data/raw with its size, modified date, row count (for CSVs) and an Message-Digest Algorithm 5 (MD5) hash. Flag exact duplicates. Explain why hashing beats comparing file names.

B.4 Profile before you trust

Prompt 4.1 — profile in one line

Use DuckDB’s SUMMARIZE to profile fmcg_sell_out.csv. Show column type, min, max, approximate distinct count, null percentage and mean. Then tell me in plain English the three most suspicious things in the output.

Prompt 4.2 — duplicate hunting

For fmcg_sell_out.csv, count (a) exact duplicate rows and (b) duplicate business keys (week_starting, depot_code, sku). For fmcg_depots.csv, find any depot_code that appears more than once and show those rows.

Prompt 4.3 — a reusable profiler

Write an R function profile_table(con, source_sql) that returns one row per column: type, % null, distinct count, min, max, and the three most frequent values. Run it on hr_attrition.csv.

B.5 SQL: the language of the warehouse

Prompt 5.1 — have AI write SQL, then check it

Using DuckDB SQL on table gold.v_sales (columns: week_starting, depot_code, sku, units_sold, revenue_ngn, gross_profit_ngn, on_promotion, discount_pct, stockout_flag, depot_name, region, state, product_name, category, pack_size, year, quarter, year_month), write a query for “gross margin % by category and region for 2025, ranked within each region”. Use a common table expression (CTE) and a window function. Then list the assumptions you made.

B.6 Bronze: land everything, change nothing

Prompt 6.1 — bronze ingestion with lineage

Create a DuckDB warehouse with schemas bronze, silver, gold and ops. Write a function that loads a CSV into bronze. with every column as VARCHAR, and adds _source_file, _source_system and _loaded_at. Log each load (layer, table, row count) into ops.run_log. Load fmcg_sell_out.csv and show the lineage columns.

Prompt 6.2 — incremental loads with a manifest

Write ingest_increment(con, path, table) that (1) computes the file’s MD5, (2) skips it if ops.load_manifest already has that hash, (3) otherwise creates the bronze table on first load or appends with INSERT … BY NAME so new or re-ordered columns don’t break it, and (4) records the hash, file, rows and time in the manifest. Demonstrate with two deliveries of sell-out data, re-running the first to prove idempotency, and make the second delivery contain an extra column.

Prompt 6.3 — official statistics into bronze

Using R/open_data.R, pull World Bank World Development Indicators (WDI) indicators (gross domestic product (GDP) growth, inflation, GDP per capita, unemployment, remittances as % of GDP) and International Monetary Fund (IMF) World Economic Outlook series (real GDP growth, inflation, government debt) for Nigeria, Ghana, Kenya, South Africa, Egypt and Côte d’Ivoire, plus Nigeria’s 2023 exports by partner from United Nations (UN) Comtrade. Land them in bronze with their source as lineage. Then show where the World Bank and the IMF disagree about Nigeria’s inflation, and which IMF years are projections.

B.7 Silver: clean, conform, remember

Prompt 7.1 — the silver sell-out table

Write DuckDB SQL that builds silver.sell_out from bronze.fmcg_sell_out (all VARCHAR). Cast every column to its proper type. Treat blank units_sold and revenue_ngn as 0, because a blank means a stockout week (rule from the board pack Notes sheet), but keep a boolean units_was_blank as evidence. Keep exactly one row per (week_starting, depot_code, sku), preferring the earliest-loaded row. Comment every business rule.

Prompt 7.2 — slowly changing dimension (SCD) type 2

bronze.fmcg_depots lists DP04 twice (a rename). Build silver.depot_history as an SCD type 2 table: one row per depot version, ordered by load order, with valid_from (the opened date for version 1; 2025-10-01 for later versions, per a business confirmation), valid_to (the day before the next version starts) and is_current.

Prompt 7.3 — conform supplier codes

supply_chain_pos.csv has SUP-CEDAR and SUP-CEDAR-NG, which procurement confirms are the same supplier. Create a small mapping table (source_code → conformed_code, reason, approved_by) and build silver.purchase_orders with a conformed supplier_id. Show on-time delivery % before and after conforming.

B.8 Gold: model for decisions

Prompt 8.1 — a star schema from silver

From silver.sell_out, silver.products and silver.depot_history, build a star schema in gold: dim_product (with list margin), dim_depot (current version only), dim_week (year, quarter, year_month, International Organization for Standardization (ISO) week), and fct_sales at grain week × depot × stock-keeping unit (SKU) with gross_profit_ngn = revenue − units × unit cost. Then create a wide view gold.v_sales that pre-joins the star for business intelligence (BI) tools and the semantic layer, and a mart of revenue by depot and month.

Prompt 8.2 — accumulating snapshot

Using silver.purchase_orders (built in Chapter 7), build gold.fct_po_lifecycle with one row per purchase order (PO): order date, received date, promised vs actual lead days, a delivery status (on time / late / date error), and the lateness in days. Then show on-time % and average lateness by conformed supplier.

B.9 Tests and the publish gate

Prompt 9.1 — a test suite for gold

Write data tests for the retail gold layer: uniqueness of fct_sales at its grain and of each dimension key; not-null revenue; units ≥ 0; discount between 0 and 0.5; on_promotion in (0,1); fact-to-dimension relationships; at least 50,000 rows; freshness within 21 days of a given as-of date (warning only); and FY2025 revenue reconciling to the Excel regional report within 1% for every depot. Return a results table and log it.

B.10 The semantic layer: one definition of every KPI

Prompt 10.1 — compile and query

Using my metrics.yml and the metric_sql() compiler in kit.R, generate SQL for revenue, gross margin % and stockout rate by region and by quarter for 2025. Print the SQL, run it, and chart revenue by region over quarters.

Prompt 10.2 — price-volume bridge

Using the semantic layer’s units and avg_selling_price metrics, decompose the change in revenue between Q4 2024 and Q4 2025 for each category into a volume effect and a price effect (with an interaction term), and show the bridge as a table.

B.11 Vector search and AI on governed data

Prompt 11.1 — vector index for complaints

Build a vector index over silver.complaints.complaint_text using the kit’s vector_index() (term frequency–inverse document frequency (TF-IDF)), storing vectors as DOUBLE[] in DuckDB. Then search for “I can’t see my Retirement Savings Account (RSA) balance online” and “my employer did not remit my contribution”, and show the top five matches with similarity scores.

Prompt 11.2 — discover complaint themes

Cluster the complaint vectors into 8 themes with k-means. For each cluster, show its size, its most characteristic words, its share of Pidgin complaints and its average days to resolve. Name each theme in plain English.

Prompt 11.3 — a governed retrieval-augmented generation (RAG) prompt

Build a function that, for a question, retrieves the 8 most similar complaints and assembles a prompt instructing the model to answer only from those complaints, cite complaint identifiers (IDs), say “not enough evidence” if they don’t answer it, and never output personal data. Show the assembled prompt; call Claude only if ANTHROPIC_application programming interface (API)_KEY is set.

Prompt 11.4 — evaluate text-to-SQL

Build a small evaluation harness: a table of golden questions, each with a reference SQL. For each candidate SQL (from any model), run both, compare the results (same rows and values within 0.1%), and report accuracy. Include one deliberately wrong candidate to prove the harness catches it.

B.12 Serving: trusted data where people work

Prompt 12.1 — publish a serving mart

After the tests pass, publish gold.dim_depot, gold.dim_product, gold.dim_week, gold.fct_sales and gold.mart_depot_month to a SQLite file, atomically (build to a temp file, then swap). Add a view in the SQLite file that pre-joins the star for Excel users. Then prove a reader sees the right totals.

B.13 Dashboards with Quarto and Shiny

Prompt 13.1 — design critique

Here is a screenshot of my dashboard [attach]. Critique it against these principles: one decision per page, Z-pattern reading order, comparisons on every key performance indicator (KPI), definitions on hover, visible freshness and test status, accessible colour, and speed. Give the five highest-impact changes in priority order.

B.14 Operations: run it every day without you

Prompt 14.1 — a robust pipeline runner

Write run_platform() for my retail pipeline. It should: build into a temporary DuckDB file so the live warehouse is never half-built; time each step and log it; retry the ingest step up to 3 times with a back-off; run the tests; swap the new warehouse in only if the gate passes; otherwise keep the old file and raise an alert; and return a one-line status summary. Make it safe to run twice at the same time with a lock file.

Prompt 14.2 — write the runbook

Write a one-page runbook for the nightly retail platform refresh: what it does, schedule and service-level agreement (SLA), how to tell it failed, the five most likely failures with diagnosis and fix steps (source file late, schema drift, test failure, disk full, lock left behind), how to re-run safely, how to backfill a past week, and who to escalate to.

B.15 Security, privacy and governance

Prompt 15.1 — a personally identifiable information (PII) scanner

Write a function that scans every VARCHAR column of every table in a DuckDB schema and flags columns where more than 5% of a sample of values look like Nigerian phone numbers, email addresses, 11-digit identifiers (possible Bank Verification Number (BVN) or National Identification Number (NIN)), or personal names from a short list. Output a classification suggestion per column for the steward to confirm.

B.16 Playbook: Human resources

Prompt 17.1 — human resources (HR) pipeline

Build an HR pipeline with the kit’s run_pipeline(): bronze from hr_attrition.csv; silver.employees typed, with exit_interview_booked excluded because it leaks the outcome; gold.fct_employee with a compa-ratio (pay ÷ median pay for the grade), an engagement band and a promotion-wait band; and a department mart. Tests: unique employee_id, engagement 1–5, pay > 0, accepted grades and work patterns. Publish the mart to a serving SQLite file.

Prompt 17.2 — prove the leakage

Fit two logistic regressions for left_within_12m: one with exit_interview_booked (from bronze), one without (from gold). Compare their area under the curve (AUC) on a 30% hold-out. Explain to an HR director why the “better” model is useless.

B.17 Playbook: Retail chains and FMCG

Prompt 20.1 — promo uplift

Using gold.v_sales, estimate promotion uplift: for each category, compare average units per depot-SKU-week on promotion vs off promotion, within the same depot and SKU, so that big depots don’t bias the result. Then compute the incremental gross profit after discount. Which categories’ promotions pay for themselves?

Prompt 20.2 — read an A/B test properly

Analyse ab_test_checkout.csv (arm, device, converted, revenue_ngn). First check for sample-ratio mismatch (SRM) against the intended 50/50 split, overall and by device, with a chi-square test. Only then compare conversion and revenue per user between arms with confidence intervals. Explain why SRM invalidates the naive result.

B.18 Capstone: prove mastery

Prompt 26.1 — architecture brief

I am building a governed analytics platform for [decision] at [organisation] in [sector]. My sources are [list, with format and owner]. Using the six-layer architecture (sources, ingest, bronze/silver/gold warehouse, test gate, govern, serve, plus the operations and security plane), draft a one-page brief: the decision and its owner, the grain of the main fact table, the dimensions, ten data tests (including one reconciliation), eight semantic-layer metrics with owners, the serving targets by audience, and the top five privacy and operational risks.

Prompt 26.2 — red-team my platform

Act as an internal auditor and a sceptical chief financial officer (CFO). Here is my platform’s design and test results [paste]. Find the five most serious ways a wrong number could still reach a decision-maker, and for each, the control that would stop it.
