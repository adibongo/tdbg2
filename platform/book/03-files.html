3  Data comes in many shapes

🟢 Novice

What Reading comma-separated values (CSV), Excel, Parquet and JavaScript Object Notation (JSON) correctly, including messy, human-made files
Why Most errors in analytics are introduced in the first five minutes, when a file is read with the wrong types, header or encoding
When Every new source; every time a source’s format changes
Who The analyst who builds ingestion; the business owner who can explain what the file means

3.1 Know your formats

Format Structure Strengths Traps Read with
CSV / tab-separated values (TSV) Plain text, one row per line Universal; diff-able in Git No types; delimiter, quote, encoding and date-format guessing; “1,234” vs 1234 readr::read_csv, DuckDB read_csv_auto
Excel (.xlsx) Workbook of sheets, cells with formats What business actually uses Title rows, merged cells, totals, notes, hidden sheets, formulas, numbers stored as text readxl::read_excel
Parquet Columnar, typed, compressed Small, fast, keeps types; the lingua franca of data lakes Not human-readable DuckDB read_parquet, arrow
JSON Nested objects Application programming interfaces (APIs) and web apps Nesting must be flattened DuckDB read_json_auto, jsonlite
Database tables Typed rows in a server Live, governed Need credentials and network DBI::dbConnect

Reading everything as text means the bronze layer never loses information. A value like "12O" (letter O, not zero) would silently become NA under type guessing. As text, it survives, so silver can flag it.

🧠 Prompt 3.2 — tame a presentation spreadsheet

regional_report.xlsx has 4 title rows, region typed once per block (merged cells), one column per month, values as text like “₦149,023,348”, an “All depots” total row and a footnote. Turn it into a tidy table (region, depot, month as a real date in 2025, revenue_ngn as a number). Drop the total and the footnote. Then check: does the sum of depots equal the “All depots” row for January?

raw <- read_excel(raw_path("regional_report.xlsx"), skip = 4, col_types = "text")
tidy <- raw |>
  filter(!is.na(depot)) |>
  fill(region) |>                                           # undo merged cells
  pivot_longer(Jan:Dec, names_to = "mon", values_to = "txt") |>
  mutate(month = as.Date(paste("2025", mon, "1"), "%Y %b %d"),
         revenue_ngn = parse_number(txt))                   # "₦149,023,348" -> 149023348

depots <- tidy |> filter(depot != "All depots")
check  <- tidy |> filter(mon == "Jan") |>
  summarise(sum_of_depots = sum(revenue_ngn[depot != "All depots"]),
            printed_total = revenue_ngn[depot == "All depots"])
check |> mutate(difference = sum_of_depots - printed_total)
sum_of_depots printed_total difference
1450995257 1450995256 1

Read the footnote too, because it is data:

raw |> filter(is.na(depot) | grepl("^Note", region)) |> pull(region) |> na.omit()

“Abuja Central includes Wuse II from Q3” is a business rule hiding in a footnote. It explains why the depot master has two Abuja rows, which is your first clue for Chapter 7.

3.4 Parquet: the analyst’s best friend

🧠 Prompt 3.3 — why Parquet?

Convert fmcg_sell_out.csv to Parquet using DuckDB’s COPY command. Compare file sizes and the time to compute total revenue by depot from each. Explain the result in terms of row versus column storage.

con <- dbConnect(duckdb())
pq <- tempfile(fileext = ".parquet")
dbExecute(con, sprintf("COPY (SELECT * FROM read_csv_auto('%s')) TO '%s' (FORMAT parquet)", raw_path("fmcg_sell_out.csv"), pq))
[1] 55474
t_csv <- system.time(for (i in 1:5) dbGetQuery(con, sprintf("SELECT depot_code, SUM(revenue_ngn) FROM read_csv_auto('%s') GROUP BY 1", raw_path("fmcg_sell_out.csv"))))[3]
t_pq  <- system.time(for (i in 1:5) dbGetQuery(con, sprintf("SELECT depot_code, SUM(revenue_ngn) FROM read_parquet('%s') GROUP BY 1", pq)))[3]
data.frame(format = c("CSV", "Parquet"),
           size_mb = round(c(file.size(raw_path("fmcg_sell_out.csv")), file.size(pq)) / 1e6, 2),
           seconds_for_5_queries = round(c(t_csv, t_pq), 3))
format size_mb seconds_for_5_queries
CSV 3.14 0.664
Parquet 0.75 0.031

A query that needs two columns reads only those two columns from Parquet. From a CSV, it must parse every character of every row.

                  {"depot":"DP02","kpis":{"otif":0.89,"fill_rate":0.95}}]'

dbWriteTable(con, "api_kpis", parsed)                         # now it is a warehouse table like any other
dbGetQuery(con, 'SELECT depot, "kpis.otif" AS otif FROM api_kpis')

DP01 0.94

DuckDB can also read JSON files directly with read_json_auto(), once its json extension is installed. It installs automatically the first time you use it, if your network allows.

E3.3. “CSV (Comma delimited)” on Windows uses the Windows-1252 code page. Characters outside it, such as ₦ or the accented letters in names, become ? or garbled text. Always ask for CSV UTF-8, or read with locale(encoding = "latin1") and convert.

3.9 🏢 In the organisation

The cheapest data-quality fix is upstream. Once you have tidied a monthly Excel report twice, meet its author. Agree a data contract: a fixed template, no merged cells, no totals, Unicode Transformation Format, 8-bit (UTF-8), and named on a schedule. One meeting saves twelve months of cleaning code.
